# Airtable field types — write shapes

What a cell value must look like in a create/update body, per field type. A
mismatch here is the usual cause of a `422` or
`INVALID_VALUE_FOR_COLUMN`. Types marked **read-only** are computed by Airtable
and always reject a written value — the CLI blocks these before sending.

Check the target table with `schema` first: it prints every field's real name,
its type, and (for selects) the exact allowed choices.

## Writable types

| Field type | Write shape | Notes |
|---|---|---|
| `singleLineText` | `"Name": "hello"` | |
| `multilineText` | `"Notes": "line one\nline two"` | |
| `richText` | `"Notes": "**bold** text"` | Markdown subset |
| `email` / `url` / `phoneNumber` | `"Email": "a@b.com"` | Validated loosely; bad values usually pass through |
| `number` / `percent` / `currency` | `"Score": 42` or `42.5` | A JSON number, not `"42"`, unless `typecast` is on. Percent is a fraction: `0.25` renders as 25% |
| `duration` | `"Elapsed": 3630` | Seconds, as a number |
| `rating` | `"Stars": 4` | Integer within the field's configured max |
| `checkbox` | `"Done": true` | JSON boolean |
| `date` | `"Due": "2026-04-01"` | ISO date. Sending a datetime to a date field truncates it |
| `dateTime` | `"At": "2026-04-01T14:30:00.000Z"` | ISO 8601, UTC. Use `Z`, not a local offset, unless you mean it |
| `singleSelect` | `"Status": "Todo"` | Must be an existing choice unless `typecast` is on |
| `multipleSelects` | `"Tags": ["urgent", "bug"]` | Array of choice names. **Replaces** the whole set |
| `multipleRecordLinks` | `"Owner": ["rec5dNAPMJ1fcUKPX"]` | Array of **record ids** in the linked table, never names. Replaces the whole set |
| `singleCollaborator` | `"Lead": {"id": "usr..."}` | Or `{"email": "a@b.com"}` |
| `multipleCollaborators` | `"Team": [{"id": "usr..."}]` | Array of the same |
| `multipleAttachments` | `"Files": [{"url": "https://..."}]` | Airtable fetches and rehosts the URL; it must be publicly reachable. Optional `"filename"`. Replaces the whole set |
| `barcode` | `"Code": {"text": "012345", "type": "upce"}` | `type` optional |
| `aiText` | — | Generated by Airtable; not writable |

### Arrays replace, they don't append

For every multi-value field — multi-select, linked records, collaborators,
attachments — the array you send **becomes** the cell's contents. To add one tag
to a record, read the current value first and send the union; sending just the
new tag silently drops the others. This is the single most common way an
Airtable write loses data.

```bash
# Add "urgent" without clobbering existing tags
python3 scripts/airtable_api.py get-record --table Tasks --record rec... --format json
# -> {"fields": {"Tags": ["bug", "backend"]}}
AIRTABLE_READ_ONLY=0 python3 scripts/airtable_api.py update-records --table Tasks \
  --record rec... --field-json 'Tags=["bug","backend","urgent"]'
```

## Read-only (computed) types

These are derived by Airtable and cannot be written:
`formula`, `rollup`, `count`, `lookup` / `multipleLookupValues`, `autoNumber`,
`createdTime`, `lastModifiedTime`, `createdBy`, `lastModifiedBy`, `button`,
`externalSyncSource`.

They still appear in reads, and they're often exactly what you want to *filter*
on — a `formula` field holding "days overdue" is a fine `--where` target.

## typecast

Passing `typecast: true` (the CLI's `--typecast`) asks Airtable to coerce values
best-effort: `"42"` → number, `"2026-04-01"` → date, and — importantly — an
unrecognized single/multi-select value gets **created as a new option**.

That last behavior is the trap. With typecast on, a misspelling doesn't fail; it
quietly adds "In Progess" alongside "In progress" and the base is now dirty for
everyone. When writing select fields from user-supplied text, either validate
against the choices in `schema` first, or pass `--no-typecast` so a bad value
errors instead.

## Clearing a value

Send `null` (or `""` for text) for the field. There's no separate "delete cell"
operation:

```bash
AIRTABLE_READ_ONLY=0 python3 scripts/airtable_api.py update-records --table Tasks \
  --record rec... --field-json 'Owner=null'
```

Note that `PUT` (`--destructive`) clears every field you *didn't* name, which is
a much blunter instrument — use `PATCH` with explicit `null`s instead.

## Worked examples

A record touching most of the awkward types at once:

```json
[
  {
    "Name": "Migrate billing webhooks",
    "Notes": "Split into two phases.\nPhase 1 ships Friday.",
    "Status": "In progress",
    "Tags": ["backend", "urgent"],
    "Score": 8,
    "Done": false,
    "Due": "2026-04-01",
    "Reviewed at": "2026-03-28T09:15:00.000Z",
    "Owner": ["rec5dNAPMJ1fcUKPX"],
    "Lead": {"email": "dana@acme.io"},
    "Spec": [{"url": "https://acme.io/specs/billing.pdf", "filename": "billing.pdf"}]
  }
]
```

Written with:

```bash
AIRTABLE_READ_ONLY=0 python3 scripts/airtable_api.py create-records \
  --table Tasks --records-file rows.json
```

Because the file carries real JSON types, `typecast` stays off and a wrong
select value fails loudly — which is what you want for a batch.
